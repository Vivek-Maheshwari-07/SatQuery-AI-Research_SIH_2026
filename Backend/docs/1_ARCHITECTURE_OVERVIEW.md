# Architecture Overview: SatQuery AI Research Pipeline

## 1. System Philosophy
The SatQuery backend is designed with strict adherence to **Single Responsibility Principle (SRP)**, **SOLID principles**, and **Atomic Component Design**. 
Every component in the system is completely decoupled, ensuring that models, graph states, schemas, and routes can be modified without breaking adjacent components.

## 2. Tech Stack
- **Framework**: FastAPI + Uvicorn (Provides extreme performance, async support, and native Pydantic validation)
- **AI/LLM Layer**: Groq (SDAIA/Allam Hackathon Model: `allam-2-7b`) using Langchain prompt engineering.
- **Orchestration**: LangGraph (StateGraph)
- **Environment**: Docker & Docker Compose (Python 3.11-slim)

## 3. The 3-Layer Pipeline Architecture

The core of this system is the Pipeline Graph (`app.graph.builder.PipelineGraph`). It executes user queries sequentially through 3 abstracted layers.

### Layer 1: Gatekeeper / Validator
- **Responsibility**: Validate image paths, verify image modalities (Optical, SAR), and determine if the text query makes logical sense for the provided images.
- **Output**: `ValidationRoute` dictionary (Tells Layer 2 which specialist agent to trigger).
- **Core Files**: `app/agents/layer_1/`

### Layer 2: Specialist Planning Agents
- **Responsibility**: Breakdown a complex natural language query into a strict JSON-based Directed Acyclic Graph (DAG) of executable ML steps.
- **Agents Available**:
  - `SingleImageAgent`: For queries on a single satellite image.
  - `CrossModalAgent`: For queries requiring Optical + SAR fusion.
  - `ChangeDetectionAgent`: For temporal analysis of the same region across different dates.
- **Core Files**: `app/agents/layer_2/`

### Layer 3: Model Execution Layer (PENDING)
- **Responsibility**: Parse the DAG generated by Layer 2 and physically execute the requested ML models (YOLO, GroundingDINO, SAM) sequentially.
- **Status**: Design phase (See `4_LAYER_3_EXECUTION_GUIDE.md` for strict implementation instructions).

## 4. State Management (LangGraph)
The pipeline state is stored in an atomic dictionary `AgentState` (`app/schemas/state.py`). 
All states strictly use raw Python `dict`s to avoid LangGraph serialization crashes. Pydantic objects are dumped (`.model_dump()`) before entering the state.
